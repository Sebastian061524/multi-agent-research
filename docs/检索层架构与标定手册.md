# 检索层 · 架构与标定手册

> **这份手册是「干活时翻的」，不是「学习时读的」。**
> 为什么每个结论成立、当初错了几次 —— 见 [`检索开发实录.md`](检索开发实录.md)（14 课 / 18 专题 / 27 条教训）。
>
> 本手册只回答三个问题：
> 1. 现在的检索层**长什么样**（每一层在干什么、哪个参数管哪件事）
> 2. 换一个新语料，**按什么顺序标定**
> 3. 出了问题，**先查哪一层**

---

## 一、架构：六层，一层一个旋钮

```
语料 research_docs/*.txt
   │
   ├─ ① 切块        按 "\n\n" 切 + 丢 ≤20 字        → 7 段，每段记 start/end
   │
   ├─ ② 表示        向量：bge-small-zh-v1.5 (512d, 已归一化)
   │                稀疏：手写 BM25（汉字 bigram + 53 字停用词表）
   │
   ├─ ③ 召回        向量 top-k  ∪  BM25 top-k        → coarse_k = 20（并集，不融合）
   │
   ├─ ④ 精排        bge-reranker-base（CrossEncoder，输出是 sigmoid 后的概率）
   │
   ├─ ⑤ 判定        rr_score ≥ RERANK_THRESHOLD      → 0.9（本语料标定值）
   │
   └─ ⑥ 输出        最多 max_k = 5 段
```

| 层 | 现在用什么 | 旋钮 | 改它会影响什么 |
|---|---|---|---|
| ① 切块 | `\n\n` 切 + 长度过滤 | 块大小 / 留不留标题 / overlap | **决定「哪些内容有资格被检索到」** —— 最底层 |
| ② 表示 | BGE 向量 + 手写 BM25 | 嵌入模型 / 停用词表 | 「语义相似」和「字面精确」的偏向 |
| ③ 召回 | **并集**（不是融合） | `coarse_k` | 精排成本 ↔ 漏召回风险 |
| ④ 精排 | `bge-reranker-base` | 换模型 | 最终排序 / 能否作答的判断 |
| ⑤ 判定 | **绝对阈值** | `RERANK_THRESHOLD` | 精确率 ↔ 召回率 |
| ⑥ 输出 | `max_k = 5` | `max_k` | 上下文长度 |

### 三个不能忘的结构性事实

**① 这是串联链路，优化必须在瓶颈上做。**

```
召回 → 精排 → 阈值 → 结果
```

**例**：候选池召回从 85.71% 提到 100%（真实提升），**最终结果 0/19 变化** —— 因为精排给那些段落的分数是 0.0073，阈值照样砍。

> **任何一层指标的改善，都要用整条链路的结果复核。**

**② `coarse_k` 必须小于语料段数，召回层才真的在「筛」。**

当前 `coarse_k = 20` 而语料只有 **7 段** → 候选池 = 全集 → **召回层是空转的**（加什么都是全集）。

这不是 bug：`coarse_k = 20` 是**按未来语料规模**设的。**语料超过 20 段时它才开始真正工作。**

**③ 精排判的是「这一段能不能回答这个查询」，判得很准。**

所以它给低分，通常意味着 **真的没有单段能回答** —— 尤其对**复合问题**：

```
「A 和 B 有什么不同」→ 语料里没有一段同时覆盖 A 和 B → 所有段落分数都接近 0
```

**解法不是换模型、不是调阈值，是查询分解。**

## 二、换一个新语料：标定流程

> 顺序不能颠倒。**每一步都为下一步提供前提。**

### Step 0 · 建语料地图

把语料读一遍，列一张表：

| 下标 | 讲什么 | 里面**没写**的（后面要用） |
|---|---|---|
| [0] | … | … |

**「里面没写的」那一列最重要** —— 它直接变成「近似无答案」类评测查询的来源。

### Step 1 · 切块，并记录原文字符区间

**必须记录 `start` / `end`。** 否则下一步的 gold 会锚在「段落下标」上 —— 那是切块的产物，换切法就失效。

```python
offset = 0
for raw in text.split("\n\n"):
    start = offset
    offset += len(raw) + 2
    para = raw.strip()
    if len(para) > 20:
        chunks.append({"text": para, "start": start + lead, "end": ...})
```

### Step 2 · 标注评测集

| 类型 | 建议条数 | 作用 |
|---|---|---|
| 直接 | 20% | 用文档原词 |
| 换词 | 20% | 意思一样，但不出现关键词 |
| 多概念 | 15% | 需要不止一段 |
| **近似无答案** | **30%** | **主题相关，细节库里没有** ← 主战场 |
| 无关 | 10% | 完全不相干 |

**三条纪律**：

1. **人工标注**，不要用 LLM 判分
2. **`gold` 的语义是「能回答」**，不是「相关」
3. **标注前不许看检索结果**（否则答案被被测系统带偏）

**gold 锚定在 Step 1 记录的原文字符区间上**（`CHUNK_SPANS`），不要锚在段落下标上。

### Step 3 · 体检（每次都做，几秒）

```powershell
python -m retrieval.check_eval_set
```

**看两件事**：

| 检查项 | 报警意味着 |
|---|---|
| **gold 的下标分布** | 某一段占了 >50% → 大概率是复制 query 时忘了改 gold，尺子会「永远显示及格」 |
| 类型分布 | 「应该拒答」的占比 <30% → 主战场没被测到 |

### Step 4 · 量基线（**这一步不能跳**）

```powershell
python -m retrieval.evaluate
```

**四个数一起看，缺一个就少一只眼睛**：

| 指标 | 只看得见 | 看不见 |
|---|---|---|
| **召回** | 该找到的漏没漏 | 多给的 |
| **精确** | 多没多 | 漏了的 |
| **MRR** | 第一个对的排第几 | 前后的噪音 |
| **拒答** | 该不该答 | — |

⚠️ **还要记「成本」**：每次查询平均要塞多少字符进 prompt。

> **任何「越大/越多/越全」的方向，指标里没有成本维度，优化一定会滑向平凡解。**

### Step 5 · 逐层标定

**只动一个变量，一次只改一处。**

#### 5a · 切块

```powershell
python -m retrieval.chunk_lab
```

跑 4 种切法 × 2 种阈值（**必须交叉**：切块大小和阈值是耦合的，短块分数天然偏低）。

**判读**：

| 现象 | 结论 |
|---|---|
| 固定阈值下，某切法在**两种阈值**下都崩 | **真的不行**（不是阈值问题） |
| 切法在紧阈值下崩、松阈值下好 | 是阈值不适合这个粒度，不是切法不行 |
| 「更粗」质量小涨但成本大涨 | **不划算**，看趋势终点是不是平凡解 |

⚠️ **切块粒度必须和查询粒度匹配**：按句切会把「优缺点」这种需要多句的答案拆散 → 全部答不了。

#### 5b · 召回

```powershell
python -m retrieval.recall_lab     # 只看召回层：k=1…7 的召回曲线
python -m retrieval.hybrid_lab     # 向量 / BM25 / BM25+停用词 / 融合
```

**关键前提**：`k` 必须小于语料段数，否则候选池 = 全集，**什么都测不出来**。

**判读**：

| 现象 | 结论 |
|---|---|
| k=1 召回低 | 排序能力不足 → 看精排，或加大 k |
| k 涨了但最终指标不动 | **瓶颈在下游**，别在召回层耗了 |
| BM25 单独打赢向量 | 语料同域、查询依赖精确词 → 正常 |

**BM25 的中文注意**：必须处理 token（汉字 bigram）+ **停用词表**（否则「有什么不同」会去匹配语料里的「应该做什么」，同字不同义）。

#### 5c · 精排 + 阈值

```powershell
python -m retrieval.rerank_probe   # 扰动实验：固定段落，只改查询的某一方面
python -m retrieval.gold_review    # 复查 gold：找出所有「多给了」的查询，算分差
```

**标定阈值的方法**：把「多返回」的段落按**分差**分档。

| 分差 | 阈值能救吗 |
|---|---|
| **< 0.01**（几乎并列） | ❌ 救不了 —— 分数饱和，没有分辨率 |
| **> 0.1** | ✅ 能救 |

然后取「要砍的最高分」和「要保的最低分」之间的值。

**⚠️ 绝对阈值不能跨语料搬。**

它依赖「相关段落的分数都挤在高位」这个语料特性。真实语料（跨领域、上千段）里，一个**确实相关但不够完美**的段落可能只有 0.6~0.8 —— 高阈值会把它砍掉，**从「精确率低」变成「漏召回」**。

### Step 6 · 验证 + 记录

1. **回归**：改造后如果被测对象没变，指标必须**一模一样**（见第四节）
2. **留出集**：新写一批（**没参与标定的**），只看一次。看完不许回头调参
3. **写进代码注释**：参数的**值**和**标定条件**必须写在一起

## 三、症状 → 先查哪一层

按这个顺序，**别跳**：

```
第 0 问：这个查询是不是复合的？（A 和 B 有什么不同 / 分别 / 对比）
   ├─ 是  → 【查询分解】。不是召回问题，不是阈值问题。
   └─ 否  → 往下
        │
第 1 问：gold 有没有进候选池？
   ├─ 没进 → 【召回层】→ recall_lab / hybrid_lab
   └─ 进了 → 往下
        │
第 2 问：gold 的精排分是多少？
   ├─ 接近 0（<0.1）→ 【问题不在检索】—— 这一段确实答不了这个查询
   │                  换个角度看：是不是 gold 标错了？是不是该拆？
   ├─ 中等（0.1~0.85）但被阈值砍 → 【阈值】
   └─ 高（>0.9）→ 往下
        │
第 3 问：它排第几？
   ├─ 排后面 → 【精排】
   └─ 排第一 → 检索这一环没问题，问题在生成
```

**配套工具**：

| 想知道 | 用 |
|---|---|
| 每一级的分数 | `anatomy.py` / `diagnose.py` |
| 只有召回层的表现 | `recall_lab.py` |
| 整条链路的表现 | `evaluate.py` |
| 精确率低是谁的错 | `gold_review.py` |
| 精排到底在判什么 | `rerank_probe.py` |
| 换切块会怎样 | `chunk_lab.py` |

## 四、信任一个数字之前的三个检查

**这把尺子坏过三次，每次都不报错。**

| 层次 | 坏法 | 怎么查 |
|---|---|---|
| **刻度值** | `gold` 标错（8 条全填 `[0]`） | 统计 **gold 的分布** |
| **刻度选择** | 漏了精确率 / 选了结构上会饱和的指标 | 问「这个指标在什么情况下会变坏」 |
| **量的对象** | 测的不是真正在用的那条路 | **去读真正在用的调用点** |

**再加两条**：

| 检查 | 说明 |
|---|---|
| **锚点会不会随被测对象变** | 换切块 → `gold` 失效，说明锚点（段落下标）选在了被测对象的**产物**上。**判据：去改变被测对象，看尺子还准不准。** |
| **重构后数字有没有变** | 换了实现、没换被测对象 → 指标必须**一模一样**。变了就是新实现写错了 |

## 五、已知边界（这套东西什么时候不成立）

| # | 边界 | 影响 |
|---|---|---|
| 1 | 语料只有 **7 段** | `coarse_k=20` > 7 → **召回层空转**；很多结论是「小语料下的」 |
| 2 | 阈值 **0.9** 是在本语料标定的 | 依赖「gold 段分数 ≥0.93」；真实语料要重标 |
| 3 | 评测集 **19 条**（14 个 gold） | **1 个 gold = 7.14%**，小差异可能是巧合 |
| 4 | `decompose` 用 LLM，**有随机性** | 同一策略两次跑，指标会有 **0.05 量级抖动** |
| 5 | **单语料、单领域** | 没测过跨领域、跨文档、长文档 |
| 6 | 只有 **1 个文档** | 多文档的去重 / 冲突处理没验证过 |
| 7 | 没有 **overlap** | 相邻块之间的上下文是断的 |
| 8 | 精排只测过 1 个模型 | 换 reranker 没比过 |

## 六、参数标定记录表（模板）

**每个参数都填一张**。没有标定条件的参数值，等于谣言。

| 字段 | 填什么 | 示例 |
|---|---|---|
| **参数名** | | `RERANK_THRESHOLD` |
| **值** | | 0.9 |
| **标定语料** | 哪份语料 | `sample_ai_agents.txt`（1037 字符 / 7 段） |
| **标定数据** | 哪个评测集、多少条 | 训练集 19 条 |
| **标定方法** | 怎么比出来的 | 把「多返回」段落按分差分成 `<0.01` / `>0.1` 两档 |
| **改前 → 改后** | 四个指标 + 成本 | 精确 0.76→0.91，拒答 7/8→8/8，召回/MRR 不动 |
| **为什么是这个值** | 区间推导 | `0.8525 < 阈值 < 0.9310` |
| **什么时候会失效** | 换语料 / 换领域 / 语料规模变化 | 真实语料里相关段落可能只有 0.6~0.8 → 会变成漏召回 |
| **怎么重标** | 具体命令 | 改值 → `python -m retrieval.evaluate` → 看四个指标 |

**现有参数的标定记录**：

| 参数 | 值 | 标定语料 | 失效条件 |
|---|---|---|---|
| `RERANK_THRESHOLD` | **0.9** | 7 段 / 19 条训练集 | 换语料，特别是跨领域大语料 |
| `coarse_k` | **20** | 按「未来 20~1000 段」预估 | 语料 <20 段时空转（无害） |
| `max_k` | **5** | 经验值 | 上下文预算变化 |
| `COVER_RATIO`（评测用） | **0.5** | 判定「覆盖了 gold」 | 改它等于改尺子，会影响精确率 |
| `BM25 k1 / b` | **1.5 / 0.75** | BM25 论文默认值，**未标定** | 未测 |

## 七、一句话总结

> **先建尺子，再动手。**
> **一次只动一个变量。**
> **指标要能看见所有方向 + 成本。**
> **尺子的锚点，别选在被测对象的产物上。**
> **观察（一个数）只能提假设，全链路指标才能验证假设。**
> **有数据支撑的「不用改」，和没试过的「不用改」，是两件事。**
