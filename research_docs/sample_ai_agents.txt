大语言模型 Agent 的主流架构

ReAct 架构
ReAct 是最经典的 Agent 架构，核心思想是「推理-行动-观察」循环。模型先思考当前应该做什么，然后调用工具执行行动，观察结果后再决定下一步，这个循环持续到任务完成。ReAct 的优点是简单可靠、易于实现；缺点是对于复杂任务容易陷入局部最优，缺乏全局规划。

Plan-and-Execute 架构
Plan-and-Execute 先让模型制定完整的执行计划，再逐步执行计划中的每一步。相比 ReAct 的「边想边做」，它更适合需要全局规划、步骤较多的任务。缺点是一旦计划出错，后续执行会全部偏离，因此通常需要配合重规划机制使用。

多 Agent 协作
多 Agent 架构把复杂任务拆分给多个专职 Agent。常见模式包括 Orchestrator-Worker（编排者-执行者）、Pipeline（流水线）、Debate（辩论）、Hierarchical（层级）。多 Agent 的优势是职责分离、可并行执行、上下文隔离；缺点是复杂度和成本显著上升，调试困难。经验法则是：能用一个 Agent 解决的问题，不要拆成多个。

RAG 检索增强生成
RAG 通过在生成之前检索相关文档，让模型基于事实回答，从而减少幻觉。典型流程是：文档切块、向量化、检索、注入提示词、生成答案。进阶方案包括混合检索（关键词加向量）、重排序（rerank）、查询改写等。RAG 的评测通常关注检索召回率和答案忠实度。

Agent 的记忆机制
Agent 的记忆分为短期记忆和长期记忆。短期记忆是当前对话的上下文，受限于模型的上下文窗口大小。长期记忆通常用向量数据库存储，通过检索按需召回。记忆管理的关键挑战是上下文会不断累积，旧信息可能污染新的判断，因此需要定期摘要或清理。

Agent 的可观测性
可观测性指追踪 Agent 内部每一步的执行情况。常用工具包括 Langfuse、LangSmith 等。它们能记录每一次 LLM 调用的输入输出、token 消耗、耗时，以及工具调用的参数和结果。可观测性是调试 Agent 的基础，没有它就只能靠打印日志盲猜。

Agent 的评测方法
Agent 评测通常需要构建测试集，包含一系列问题及其标准答案。评分方式有两类：一是关键词匹配，快速但粗糙；二是 LLM 作为裁判，让另一个大模型判断答案是否正确，更接近人类判断。评测的意义在于量化改进效果，避免盲目调整提示词。
